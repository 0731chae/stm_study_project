# 시스템 요구사항 명세서

프로젝트: 조기 화재 진압 시스템 / 팀명·팀원 실명: 미정(4인) / v0.1 초안 / 2026-10-27.
참고 양식: 사용자 제공 `01_시스템_요구사항_명세서.pdf`.
부품 모델·배선·실측 기준은 미정이며, 아래 추가 기능·수치는 개발 시작을 위한 제안입니다. 검토 후 기준 버전을 확정합니다.

## 1. 프로젝트 개요

목적은 제한된 실험 환경에서 센서 입력으로 화재 후보를 조기에 감지하고 방향 모터와 물 펌프를 제어하는 시제품을 만드는 것입니다. STM32가 핵심 판단과 제어를 수행합니다.

구현 범위: 센서 취득, 연속 감지, 목표 방향 검증, 조준, 시간 제한 분사, 오류/비상정지, UART 관측 로그, 요구사항-설계-시험 추적.
제외 범위: 건물 전체 소방 설비, 실제 시설 설치·인증, 원격 앱/서버, 화재 종류 자동 분류, 진압 성공의 자동 보증. 센서·진화 성능 시험 환경은 부품 선정 후 정의합니다.
사용자·환경: 팀원/평가자, 감독되는 실내 실험대, MCU와 구동 전원 분리 설계. 구체 장소·전원·시험 대상은 미정입니다.

| 단계 | 입력·조건 | 시스템 동작 |
| --- | --- | --- |
| 1 | 전원 ON, 정상 센서·화재 없음 | 출력 OFF, 초기화, IDLE |
| 2 | 연속 3개 유효 화재 후보와 유효 목표 각도 | AIMING 진입, 펌프 OFF, 목표 방향 명령 |
| 3 | 같은 목표로 조준 대기시간 경과, 감지 유지 | SPRAYING, 최대 분사시간 제어 |
| 4 | 감지 해제 또는 최대시간 경과 | 펌프 OFF, COOLDOWN 후 재감시 |
| 5 | 오류 또는 비상정지 | 출력 OFF, 래치. 정상 입력과 수동 reset으로만 복구 |

## 3. 기능 요구사항

전 기능은 필수 초안입니다. 입력의 valid·각도·시간 기준은 [인터페이스](interfaces.md)를 따릅니다.

| ID | 기능·조건 | 동작·완료 기준 | 연결 TC |
| --- | --- | --- | --- |
| FR-001 | 센서 취득 | 실제 취득 시각을 포함한 스냅샷 제공, 실패/미래/역순/250ms 초과 입력을 오류로 구별 | 008,009,017,019,020,101,102 |
| FR-002 | 연속 화재 확인 | 3개 연속 새 alarm=true 샘플에서 확정. 정상 입력 또는 취득 간격 250ms 초과 시 횟수 초기화, 중복 시각 제외 | 002,003,004,020,102 |
| FR-003 | 목표 방향 검증 | 논리 각도 0~180도만 허용. 확정 감지에 target_valid=false이면 분사 금지 및 TARGET 래치 | 010,011,103 |
| FR-004 | 조준 | 확정 감지 시 모터 요청, 펌프 OFF. 같은 목표로 500ms 이후 분사 허용. 목표 변경 시 분사 중단·재조준, 감지 해제 시 조준 취소 | 005,014,018,103 |
| FR-005 | 펌프 제어 | SPRAYING에서만 ON. 최대 3000ms 또는 감지 해제 시 OFF. 5000ms COOLDOWN 중 재분사 금지 | 006,007,104 |
| FR-006 | 비상정지 | 비상 입력은 reset을 포함한 모든 입력보다 우선. 출력 OFF 및 ESTOP 유지. 입력 해제만으로 자동 복구하지 않음 | 012,013,105 |
| FR-007 | 초기화·오류 복구 | 초기 출력 OFF. 센서/시간/각도/설정 오류 래치. 유효하고 신선한 정상 입력 + 비상 해제 + 수동 reset에서 IDLE 복구. 잘못된 설정은 재설정 필요 | 001,008,009,013,015,016,017,019,106 |
| FR-008 | 상태 UART | STM32에서 PC로 상태/오류/출력 요청을 전송. 제어를 지연시키지 않음. 규약은 interfaces.md 초안 | 107 |

TC 번호는 TC- 접두사를 생략한 것입니다. 프레임 내 시간 경과만으로 실제 센서 정상·조준 완료·펌프 회전을 판단하지 않습니다.

기능 예외 상세: FR-001 오류는 ERR-001/002, FR-003은 ERR-003, FR-007 설정 오류는 ERR-004, FR-006은 ERR-005로 전달합니다. 제어 API의 반환은 요청이며 실제 출력 실패 검출/복구는 포트 구현 시 설계에 추가합니다. 감지가 계속되면 쿨다운 이후 재조준·재분사가 가능한 초안이며, 총 반복 횟수/물 부족 제한은 부품 검토 후 결정합니다.

## 4. 비기능 요구사항 (실측 전 제안)

| ID | 기준·조건·단위 | 측정 방법·TC |
| --- | --- | --- |
| NFR-001 | 정상 운전 센서 취득 주기 50ms ±10ms, 100회 | 실제 타임스탬프/로직 분석기, TC-101 |
| NFR-002 | main loop 주기 목표 10ms ±2ms. 확정 이벤트에서 제어 요청 갱신까지 최대 20ms, 100회 | GPIO 계측 및 UART 관측 보조, TC-108 |
| NFR-003 | 실제 펌프 ON 지속시간 3020ms 이하(논리 상한 3000ms + 제어·출력 허용 20ms), 10회 | 제어 신호·전류 동시 계측, TC-006/104 |
| NFR-004 | 정상 입력으로 30분 운전, 의도하지 않은 분사·리셋 0회 | 장치 상태 로그·출력 계측, TC-108 |

PC의 가상 시간 시험은 MCU 지연·실제 지속시간을 증명하지 않습니다. 감지 거리/외란 오탐률, 조준 오차, 진압 시간·유량 기준은 부품·실험 대상 선정 후 추가하고 ID를 새로 부여합니다.
