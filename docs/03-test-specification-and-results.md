# 테스트 명세 및 결과서

프로젝트: 조기 화재 진압 시스템 / 4인(실명 미정) / v0.1 초안 / 2026-10-27.
참고 양식: 사용자 제공 `03_테스트_명세_및_결과서.pdf`.
기준: 요구사항/설계 v0.1, 시험 대상 소스는 [검증 증거](evidence/initial-verification.txt)의 파일별 SHA-256으로 식별합니다.

## 1. 테스트 계획

PC 자동 시험은 공통 C의 입력 검증, 상태 전이, 논리 시간, 오류·복구를 확인합니다. 실제 센서·모터·펌프, 보드 링크·HAL·업로드·배선·감지 성능·조준·유량·진압 효과는 제외합니다. Cortex-M4 object 컴파일도 별도 확인하며 장치 실행을 대체하지 않습니다.
시험 담당: 감지 B/진화 B, 교차 검토: 감지 A/진화 A(실명 미정). 일정은 team-plan.md를 따릅니다.
시작 조건: PC 도구 설치·빌드 가능. HW 시험은 부품/배선/전원 확정과 출력 OFF 검토 후 시작합니다.
최종 합격: 필수 TC 모두 Pass, FR/NFR/CON 검증 기준 충족, 핵심 제어 미해결 결함 없음. 현재는 개발 기반 검증 단계입니다.

## 2. 환경·재현 조건

| 항목 | PC 시험 | 장치 시험 |
| --- | --- | --- |
| HW | Windows PC, 실제 출력 없음 | 보드 리비전·부품·전원·핀맵 미정 |
| 도구 | GCC 16.1.0, CMake 4.4.1, Ninja 1.13.2, Python 3.12 | CubeIDE/HAL 기준 버전은 보드 프로젝트 생성 시 고정 |
| 입력 | C 고정 sample/time, TC별 새 인스턴스 | 기준 자극·거리·각도·계측기는 선정 후 기록 |
| 초기 상태 | 기본 config, fire_system_init | 출력 OFF·배선·초기 설정·로그 확인 |
| 증거 | 파일별 SHA-256과 명령/실제 출력 | TC ID·commit·일자·실행자·측정값·사진/로그/영상 |

재현 명령:

```sh
python tools/verify.py
# 선택: MCU object 검사도 수행
python tools/verify.py --arm-compiler arm-none-eabi-gcc
```

새 증거는 `build/host/verification.txt`에 기록됩니다. 검토 후 docs/evidence/에 보존합니다. 소스 fingerprint가 달라지면 기존 Pass를 새 버전의 결과로 사용하지 않습니다.
개별 시험: `ctest --preset host -R '^TC-012$' --output-on-failure`.
Pass는 모든 기대 결과 충족, Fail은 실행 후 불충족, Blocked는 환경/선행 결함으로 실행 불가, Not Run은 실행 전입니다. 기대 결과는 실행 전에 정하고 실제 결과는 관측한 값으로 기록합니다.

## 4. 결함·재시험

PC 최종 실행에서 미해결 실패는 없습니다. 부품 미정, HAL·출력 포트·실제 IO 실패 검출 미구현, 실측 기준 미확정은 개발 잔여 항목입니다.
Fail/Blocked 발생 시 GitHub 결함 양식에 BUG ID, 발견 commit·TC·날짜·발견자, 배선·입력·절차·재현율, 기대/실제, 영향도·담당, 원인·수정 commit을 기록합니다. 같은 조건 재시험 및 영향받는 회귀 TC·측정값·증거를 남긴 후 Fixed→Verified로 바꿉니다. 재시험 증거는 새 파일로 보존하고 요약에는 TC별 최신 결과만 반영합니다.
